The draft is the explanation

apeCAD is a standalone Python library: a spatial language that humans and agents share. You put down a labeled 3D draft. Downstream libraries consume it. The drawing window is a client. The Python document is the language.

Put down a draft

Points, lines, boxes, labels. Not a paragraph about a building.

The window is a client

The scratchpad emits ops. It does not own geometry, undo, or names.

Others realize it

apeGmsh meshes. apeSteel takes the frame. Studio shows and picks.

01

Is / is not

Is

  • A 3D scratchpad — the explanation artifact
  • The Python document as source of truth
  • A localhost canvas that emits ops
  • A service to apeGmsh, apeSteel, Studio
  • Simple, versatile, and small

Is not

  • SolidWorks, FreeCAD, or a parametric modeller
  • A second Gmsh session
  • Studio as CAD — Studio shows and picks
  • A solid kernel (no OCCT in v0)
  • A replacement for the apeGmsh geometry session
02

The language

  1. Document In-memory Python object that is the draft. Labels are the handles agents and Studio use.
  2. Ops Typed commands mutate the document. The scratchpad posts the same JSON the API speaks.
  3. Realize If the draft is clean enough, apeGmsh makes geometry and mesh. apeSteel consumes nodes, members, section ids. That is a bonus — not the definition of success.
03

Door

One process, one document. Sketch on the XY plane (z = 0). The canvas posts ops to Python. 

git clone https://github.com/nmorabowen/apeCAD.git
cd apeCAD
pip install -e ".[dev]"
python -m apeCAD

Opens http://127.0.0.1:8765 (or the next free port). python -m apeCAD --no-browser --port 8765 if you already have a tab.
